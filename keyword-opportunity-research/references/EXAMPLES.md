# Examples

## Example A — Keyword Seed

用户：
`研究 image upscaler，重点找小而美 SaaS 机会`

正确开始：

1. S001 搜原始 `image upscaler`，建立 raw intent baseline。
2. 从真实 SERP / PAA / 页面 snippet 提取 `printing`, `product images`, `anime`, `batch`, `face` 等候选。
3. 不直接宣布某个机会。
4. 比较候选证据强度。
5. 若 `printing` 在多个来源出现，创建新 Step 搜 `upscale image for printing`。
6. 若后续出现 `300 DPI`，先验证它是 metadata conversion 还是增加像素的 print workflow。
7. 若再出现 `DTF`, `POD`, `large print`，分别标明首次来源，再决定是否下钻。
8. 只有到用户痛点、独立 SERP 与商业信号较完整时，才收敛产品机会。

错误做法：

- 一开始直接搜 `image upscaler for DTF`，然后声称这是从 Seed 自然发现。
- 因为某 Vendor blog 写 `batch` 就说“有强搜索需求”。
- 用 `site:vendor.com batch upscale` 找到文章后，写成原关键词 SERP 的自然结果。

## Example B — Website Seed

用户：
`研究 https://example.com/`

正确开始：

1. S001 做 SITE_EXPLORATION。
2. 记录检查过的 Header/Footer/Tools/Use Cases/Pricing/Blog/Docs 等 discovery surfaces。
3. 形成 page inventory。
4. 从页面保留 Vendor Phrase 原文。
5. 将值得测试的 Phrase 单独转成 Candidate Query，并解释为什么这样改写。
6. 在开放 Web 做 SERP_TESTED。
7. 如果 SERP 暴露更自然说法，将 Vendor Phrase 标为 `REPHRASED`，而不是覆盖原文。

## Example C — 会话输出

用户：
`研究 image upscaler`

行为：

- 所有研究步骤直接输出在当前会话。
- 展示 S001、S002...。
- 每个 Step 都展示 Query / URL、为什么做、原始证据、分析、决策、下一步。
- 每个阶段补一张 Current Research State 和 Discovery Graph。
- 长研究可分阶段输出，但不能只给最终“故事”。

# Profile: Product Review

## 目标

帮助读者判断：

> 这个产品是否适合我的需求，为什么？

适合：

- 单品评测
- software / SaaS review
- 工具评测
- 产品对比中的单产品段落
- buying guide 中的产品评价

## Publication Mode

通常建议 `editorial`。

产品规格、厂商声明、价格、测试结果、主观体验属于不同证据类型，不要混写成同一种“事实”。

## 信息分类

尽量区分：

### Specs / Stated Facts

例如：

- 尺寸；
- 重量；
- 官方功能；
- 支持平台；
- 套餐限制。

### Observed Experience

只有上游 context 明确存在第一手测试或可公开 observation 时才能写成亲测体验。

### Editorial Judgment

例如：

- 更适合谁；
- 某限制在特定工作流中是否重要；
- 优缺点权衡。

判断必须能从允许发布的 facts 合理推出，不能创造“手感很好”“体验顺滑”等伪体验。

## 默认结构

```text
Verdict
Best For / Not For
Key Strengths
Key Limitations
Important Specs / Capabilities
Real Workflow Implications
Value / Pricing Context
Alternatives or Comparison (only if supplied)
```

不必机械包含全部章节。

## Attribution

产品评测比游戏攻略更可能需要有限 attribution。

例如厂商规格可写：

```text
The manufacturer lists the battery life as up to 12 hours.
```

如果 context 要求 attribution，就保留。

不要写：

```text
According to our extensive research across multiple competitor reviews...
```

## 禁止伪第一手体验

除非 context 明确提供 first-party test evidence，否则不要写：

- “we tested”；
- “in our testing”；
- “I used it for a week”；
- “we noticed”；
- “the keyboard feels...” 之类需要亲测才能成立的体验。

可以改为基于事实的判断：

```text
At 1.4 kg, it is easier to carry than heavier workstation-class alternatives.
```

前提是相关重量与比较事实均在 context 中。

## 结论

Verdict 应回答适合谁、不适合谁以及关键 trade-off。

不要用“best / perfect / must-buy”除非有明确比较标准和事实支持。
